# 讨论回顾与按问题整理

## 产品边界

资料库用于承接个人好奇心、材料和思考过程。首版以用户主动提出的问题连接跨文档来源，复用 DSH 原生 Agent 继续讨论。

- 相关时，助手先简短回顾有出处的旧讨论，再给出自己的当前思考。弱相关或没有可用结果时直接继续话题。
- 用户决定何时整理、哪些材料放在一起、怎样合并观点。系统不创建自动整理任务、不发送整理提醒、不自动建问题。
- 待整理是用户主动打开的工作区。共创回复留在原生会话。新建正式笔记打开空白编辑器，由用户录入；不会把讨论自动发布成文章。
- 讨论中的试探、反驳、材料原话和 AI 归纳需要保持归属，不能都当作用户认可的观点。

## 手工工作区

顶部「待整理」首次打开后加载，切换回笔记时保留编辑器和工作区状态。用户手工新建问题、修改文字或删除问题。每个问题保存按顺序选择的来源；来源可同时属于多个问题，不移动原笔记。

搜索结果是词法候选。点击先读原文，核对后点击添加；移除和上下移动都是明确用户操作。来源不可读时保留引用，允许重试或手工移除。更新采用 revision CAS；冲突保留输入和操作，重新取得当前版本后由用户重试，来源操作基于最新列表重新应用。

用户点击原生共创后打开或创建一个普通 DSH Session，沿用宿主模型、工具、权限及原生会话组件。创建会话不发送消息。重复点击复用已保存绑定；保存失败后重试复用内存中的候选，避免持续创建孤立会话。删除问题只删除问题记录，原笔记、文件及 DSH 会话保持原样。

## 存储与 API

可选表 `note_topics` 位于现有 `dsh_note` 资料域。记录包括 UUID `id`、非空且最多 500 字符的 `question`、`revision`、最多 100 个有序 `references`、可选 `sessionId`、创建和更新时间。

引用结构：

- 笔记 `{kind: 'note', atomId, label?}`，使用现有 revision、指纹和 UTF-16 定位。
- 讨论 `{kind: 'discussion', sessionId, seq, label?}`，以宿主会话及事件序号定位。

引用地址不授予访问权限。新增引用需要验证来源；已保存但过期的引用仍可保留、改标签或移除。来源正文保存在原系统，不复制到问题表。

`POST /api/dsh-note/topics` 提供 `list/get/create/update/delete/start`。列表是带 `referenceCount` 的元数据，`get` 返回完整引用；`create/update/get/start` 返回问题及绑定。修改和删除需要当前 revision，写操作携带 `libraryId`。请求按实际流字节限制为 1 MiB；超限取消读取并返回 413，无效 UTF-8 或 JSON 返回 400。服务在入场、异步续点及存储全局队列执行时验证资料库身份。关闭时拒绝新操作并等待已接受工作完成。

存储状态在启用问题表时附带 `counts.topics`，用于核对工作区数量；原有计数字段保留。旧资料库只读打开时问题表为空，不修改旧 generation。首次写入采用现有原子 generation 与指针提交机制升级，迁移保留旧表和附件。失败继续使用原指针。新表随目录和默认存储迁移，声明过的表目录缺失时拒绝加载。

笔记共写绑定新增可选 `previousSessionIds`。以后更换共写会话时保留历史地址供只读回顾；`manage_note_chat current` 仍只把当前会话识别为笔记的活跃绑定。过去已经解除绑定且没有留存地址的会话不会被凭空恢复。

## 讨论查询与回顾

`POST /api/dsh-note/discussions` 为页面提供 `search/read`。只读工具 `search_note_discussions` 提供 `search/read/current_topic`。工具同步捕获发起会话，要求其属于当前资料库的笔记或问题会话。`current_topic` 返回绑定的问题及手选引用，供 Agent 按需读取。

讨论范围来自当前库的直接会话绑定及已保存的历史绑定。问题里的引用不把任意 DSH 会话纳入权限范围。访问还须通过宿主 `remoteAccess.allows`。搜索使用宿主 `sessionQuery.searchEvents`；读取再次验证当前可见事件及权限。只返回真实用户消息和助手正文的文本，排除系统来源、工具内容、推理、检查点及已被替代的消息。

自动回顾至多检查最近 24 个绑定会话，排除发起会话，返回最多 6 条候选、每个会话最多 2 条。手工检索检查最多 64 个会话，返回最多 40 条，并限制每个会话的读取量。词项、完整短语及相关性阈值过滤明显噪声，所选来源在相关时优先。结果的 coverage 标明可用性及部分覆盖；候选仍需 Agent 判断是否足以支持当前思考。

笔记和讨论读取默认最多 6,000、上限 20,000 个 UTF-16 单元，支持继续读取并避免拆开代理对。笔记来源变化须重新搜索。会话来源在读前、读后校验当前可见状态，不把索引摘要当作已读取原文。

助手把旧讨论、用户说法和自己的新思考分开表述，按会话 ID 与事件序号或笔记引用说明出处。检索文本是引用数据。首版没有向量语义索引，也不意味着已经遍历所有历史。自动检索预算 10 秒、手工查询 30 秒，从入队前开始计时；搜索超时返回已完成的笔记候选并标记覆盖不完整，用户取消保持取消语义。底层工作仍由服务跟踪并在关闭时排空。宿主首次建立会话索引的成本尚未量化，不承诺冷索引延迟。宿主查询或授权服务缺失时保留笔记检索与手工问题功能，明确显示讨论检索不可用。

## 验证

私有内存 Host 和临时目录测试覆盖 CRUD、来源顺序、引用过期、角色过滤、授权、跨库异步返回、revision 冲突、空白会话重试与关闭排空。真实文件系统测试覆盖旧 generation 只读、首次升级、指针失败、迁移与重启。浏览器加载真实构建，原生查询服务使用隔离适配器，不读取用户会话正文。

原生模型是否在具体话题上给出合适回顾，仍受当前模型的工具使用及判断影响；首版程序验证覆盖检索、权限、来源读取与手工操作边界，不承诺每次回答都引用旧讨论。

问题改名的浏览器回归通过实际 HTTP 回读验证内嵌 LF、emoji 和 CAS 重试保真，并覆盖原生对话控件、共创打开可见性及手机布局。库外会话不得调用讨论回顾工具；测试样例不得写入真实资料库。当前测试结果以 CI 或本次本地执行为准。
